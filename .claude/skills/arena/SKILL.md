# 아레나

N명의 하위 에이전트가 같은 과제를 서로 다른 사고 카드로 풀고, 1:1 토너먼트로 한 답만 남깁니다.
매 경기는 **공격**(서로의 답에서 FATAL·MAJOR·MINOR 결함 찾기) → **방어**(인정하거나 근거로 반박하고 답 고치기)
→ **심판**(정확성 30 · 완결성 25 · 견고성 20 · 구체성 15 · 명료성 10, 치명적 결함이 남은 답은 결함 없는 답을 못 이김)
순서이고, 진 쪽이 탈락합니다. 마지막 생존자의 답이 결과입니다.

장부(카드 뽑기, 대진, 프롬프트 파일, 판정 집계, 결과 파일)는 `scripts/arena.py`가 맡고, 당신은 하위 에이전트를 띄우는 일만 합니다.
아래에서 `ARENA`는 이 스킬 폴더의 `scripts/arena.py` 절대 경로입니다 (이 SKILL.md와 같은 폴더 아래). 파이썬 3.8+ 표준 라이브러리만 씁니다.

## 규모와 비용

| 옵션 | 참가 | 라운드 | 하위 에이전트 호출 |
| --- | --- | --- | --- |
| `--quick` | 8 | 3 | 43 |
| (기본) | 16 | 4 | 91 |
| `--agents 32` | 32 | 5 | 187 |
| `--agents 64` | 64 | 6 | 379 |
| `--full` | 100 | 7 | 595 |

호출 수 = N(풀이) + 5 × (N − 1)(경기마다 공격 2 · 방어 2 · 심판 1). 토큰은 사용자의 구독/요금에서 나갑니다.
`python3 ARENA plan --agents N` 으로 라운드별 표를 볼 수 있습니다.

## 진행 순서

### 1. 과제 정리
사용자의 요청과 지금까지 대화에서 과제를 뽑아내세요. 하위 에이전트는 **대화를 못 보고 `task.md`만 읽습니다.**
그래서 `task.md`는 그것만으로 완결되어야 합니다.

- 무엇을 원하는지, 반드시 지켜야 할 조건, 원하는 출력 형식과 분량, 답의 언어
- 대화에서 나온 배경, 이미 시도했는데 마음에 안 들었던 답과 그 이유(있다면)
- 관련 코드·문서가 있으면 절대 경로를 적어 두세요(하위 에이전트가 읽을 수 있음). 짧으면 직접 붙여 넣는 것이 더 확실합니다.
- 정답을 아는 척하거나 특정 답으로 유도하지 마세요.

과제가 너무 모호해서 좋은 답과 나쁜 답을 가를 수 없으면, 시작하기 전에 사용자에게 한 번만 짧게 물어보세요.

### 2. 규모 정하기
인자에 `--quick`/`--full`/`--agents N`이 있으면 그대로, 없으면 기본 16명입니다.
`python3 ARENA plan --agents N` 결과(호출 수)를 사용자에게 한 줄로 알리세요.
**32명 이상이면 시작 전에 사용자에게 확인받으세요.** 16명 이하는 알리고 바로 진행합니다.

### 3. 아레나 만들기
```bash
python3 ARENA init --agents N        # 또는 --quick / --full
```
출력된 폴더(`.arena/<id>/`) 안의 `task.md`에 1단계에서 정리한 과제를 Write 도구로 쓰세요.
`.arena/`는 자동으로 git에서 제외됩니다(`.arena/.gitignore`).

### 4. 루프: next → 하위 에이전트 → next
```bash
python3 ARENA next <id>
```
`next`는 지금 실행할 작업을 한 줄에 하나씩 `작업ID<TAB>프롬프트파일` 로 출력합니다.
이전 단계가 다 끝났으면 알아서 다음 단계(풀이 → 공격 → 방어 → 심판 → 다음 라운드)로 넘깁니다.

작업마다 하위 에이전트(Agent/Task 도구, `general-purpose`)를 하나씩 띄우고, 프롬프트에는 **이 한 줄만** 주세요.

> `<프롬프트파일>` 파일을 읽고 그 안의 지시를 그대로 따르세요.

- 프롬프트 파일에 카드, 읽을 파일, 출력 파일 경로, 형식이 다 들어 있습니다. 내용을 덧붙이거나 요약해 주지 마세요.
  특히 다른 참가자의 답이나 당신의 의견을 넣으면 공정성이 깨집니다.
- 서로 독립이므로 **한 메시지에 여러 개(최대 10개쯤)씩 병렬로** 띄우세요. 다 돌아오면 다음 묶음을 띄우세요.
- 하위 에이전트의 대답은 "완료"뿐입니다. 결과는 파일에 있으니 내용을 읽으려 하지 마세요(맥락 낭비).
- 한 단계의 작업을 다 돌렸으면 다시 `next`를 실행하세요. 빠졌거나 잘못된 출력(예: 읽을 수 없는 판정 JSON)이 있으면 그 작업만 다시 나옵니다.
- 출력에 `DONE`이 나오면 끝입니다.

진행 중에는 라운드가 바뀔 때마다 사용자에게 한 줄로 알려 주세요(예: "라운드 2/4 — 8명 남음").
`python3 ARENA status <id>`로 대진표를 볼 수 있습니다.

### 5. 막혔을 때
- 같은 작업이 두 번 넘게 계속 출력을 못 만들면:
  - 참가자 작업(풀이/공격/방어): `python3 ARENA forfeit <id> <agent>` — 그 참가자는 기권, 상대가 부전승.
  - 심판 작업: `python3 ARENA decide <id> <경기ID> <agent>` — 두 답을 직접 읽고 승자를 정하세요. 최후의 수단입니다.
- 세션이 끊겼다가 다시 이어 갈 때는 `python3 ARENA next latest` 부터 다시 하면 됩니다. 모든 상태는 파일에 있습니다.

### 6. 결과 전하기
`.arena/<id>/result.md`를 읽고 사용자에게 전하세요.

1. **최종 답** 전체 (`final.md`와 같음). 이것이 주인공입니다.
2. 한 문단 요약: 우승 카드(사고법 · 작업흐름 · 전략), 이긴 경기 수, 버텨 낸 공격 수(FATAL/MAJOR/MINOR), 결승 판정 이유.
3. 결과 파일 경로 (`result.md`에 경기별 점수와 대진표가 있음).

최종 답이 코드나 파일 수정이라면, 사용자가 원할 때만 실제 프로젝트에 반영하세요. 하위 에이전트는 프로젝트 파일을 고치지 않습니다.

## 지켜야 할 것

- 아레나는 "가장 좋은 답"을 보장하지 않습니다. 과제가 나쁘면 결과도 나쁩니다. 결과를 과장하지 마세요.
- 같은 모델이 서로 다른 지시로 푸는 것이지 "서로 다른 AI 100개"가 아닙니다. 사용자에게도 그렇게 설명하세요.
- 하위 에이전트 결과를 당신이 고쳐 쓰거나 승자를 바꾸지 마세요(위 `decide`의 경우 제외). 최종 답에 당신이 보기에 남은 문제가 있으면, 답은 그대로 전하고 따로 짚어 주세요.
