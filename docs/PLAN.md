# 클래시로얄 스타일 게임 — 개발 계획

## Context
빈 저장소(`memoryz`)에서 클래시로얄 같은 실시간 카드 배틀 게임을 시작한다.
결정 사항: **웹(TypeScript + Phaser 3)**, 1차 목표는 **싱글플레이 vs AI**, 그래픽은 **무료 에셋(Kenney CC0 등)**.
목표 결과물: 브라우저에서 바로 플레이 가능한 3분 1판 대전 (카드 8장 덱, 엘릭서, 타워 파괴, AI 상대).
나중에 멀티플레이를 붙일 수 있도록 **게임 로직을 렌더링과 분리**(결정적 시뮬레이션)해 둔다.

## 진행 상황
- [x] 1단계: 프로젝트 세팅 & 아레나
- [x] 2단계: 핵심 시뮬레이션 (이동, 타겟팅, 전투, 타워 파괴, 단위 테스트)
- [x] 3단계: 카드 8종, 엘릭서, 드래그/탭 배치, 배치 구역(포켓 포함)
- [x] 4단계: AI 상대 (방어/카운터/지원/마무리 파이어볼, 난이도 3단계)
- [~] 5단계: 타이머·2배 엘릭서·연장전·결과 화면 완료. 스프라이트 에셋은 아직 도형+이모지
  (이 개발 환경에서 kenney.nl 접속이 막혀 있어서 에셋을 받지 못했음)
- [ ] 6단계: 덱 편집, 밸런스 조정, 배포

## 기술 스택
- Vite + TypeScript + Phaser 3 (렌더링/입력/사운드)
- Vitest (게임 로직 단위 테스트)
- ESLint + Prettier
- 에셋: Kenney "Tiny Town"/"Tower Defense"/"Toon Characters" 등 CC0 팩 → `public/assets/` (라이선스 파일 포함). 네트워크로 받지 못하면 도형 플레이스홀더로 먼저 개발 후 교체

## 프로젝트 구조
```
src/
  core/            # 순수 로직 (Phaser 의존 X) — 나중에 서버에서도 재사용
    sim.ts         # 고정 틱(20Hz) 시뮬레이션 루프, 상태 업데이트
    state.ts       # GameState: 유닛, 타워, 엘릭서, 시간, 점수(크라운)
    entities.ts    # Unit/Tower/Projectile 타입과 스탯
    combat.ts      # 타겟팅(가장 가까운 적 / 건물만), 공격, 데미지, 스플래시
    movement.ts    # 레인 기반 이동 + 다리 통과 (그리드 or 웨이포인트)
    elixir.ts      # 엘릭서 충전(2.8초당 1, 최대 10, 마지막 1분 2배)
    deck.ts        # 8장 덱, 4장 손패 + 다음 카드 순환
    ai.ts          # AI 상대 로직
    rng.ts         # 시드 기반 난수 (결정성 확보)
  data/
    cards.json     # 카드 정의(비용, HP, 공격력, 사거리, 속도, 타겟 종류, 스폰 수)
  scenes/          # Phaser 씬
    BootScene.ts, MenuScene.ts, BattleScene.ts, ResultScene.ts
  render/          # core 상태 → 스프라이트 동기화, HP바, 이펙트
  ui/              # 손패 카드 UI, 드래그&드롭 배치, 엘릭서 바, 타이머
tests/             # core 로직 테스트
```

## 개발 단계 (마일스톤)

### 1단계: 프로젝트 세팅 & 아레나 (1~2일)
- Vite+TS+Phaser 초기화, 세로형 화면(예: 720x1280, 자동 스케일)
- 아레나: 강 + 다리 2개, 양측 킹타워 1 + 프린세스타워 2
- 결과: 화면에 맵과 타워가 보임

### 2단계: 핵심 시뮬레이션 (3~4일) ← 가장 중요
- 고정 틱 루프, 유닛 이동(자기 레인 → 다리 → 적 타워)
- 타겟팅: 사거리 내 가장 가까운 적, "건물만 공격" 유닛(자이언트형) 지원
- 공격/데미지/사망, 타워도 자동 공격
- 프린세스타워 파괴 시 킹타워 활성화, 킹타워 파괴 = 즉시 승리
- 단위 테스트로 로직 검증

### 3단계: 카드 & 엘릭서 & 배치 (2~3일)
- 엘릭서 바, 손패 4장 + 다음 카드, 드래그로 배치
- 배치 가능 영역 제한 (자기 진영, 적 프린세스타워 파괴 시 확장)
- 초기 카드 8종 예: 기사, 궁수(2기), 자이언트, 고블린(3기), 미니 드래곤(공중), 해골 군대, 화염구(주문), 대포(건물)
- 공중/지상 구분, 주문(범위 데미지), 건물(수명 감소) 지원

### 4단계: AI 상대 (2일)
- 엘릭서 여유 시 카드 사용, 위협받는 레인에 방어 카드 배치
- 간단한 카운터 규칙(공중 유닛엔 궁수 등), 난이도 3단계(반응 속도/판단)

### 5단계: 게임 흐름 & 에셋 (2~3일)
- 3분 타이머, 마지막 1분 2배 엘릭서, 동점 시 1분 연장전
- 크라운(0~3) 기반 승패, 결과 화면
- Kenney 에셋 적용, 스프라이트 애니메이션, HP바, 히트 이펙트, 효과음

### 6단계: 폴리싱 (선택)
- 덱 편집 화면, 카드 밸런스 조정(`cards.json`만 수정), 모바일 터치 최적화
- 배포: GitHub Pages / Vercel

### 이후 확장 (2차 목표)
- Node.js + WebSocket 서버에서 `src/core` 그대로 실행 → 입력만 주고받는 1:1 멀티플레이
- 계정, 트로피, 상자/카드 레벨업

## 핵심 설계 원칙
- `core/`는 Phaser를 import하지 않음 → 테스트 쉬움 + 서버 재사용 가능
- 모든 카드 스탯은 데이터(JSON)로 관리 → 코드 수정 없이 밸런싱
- 플레이어 입력은 "틱 N에 카드 X를 (x,y)에 배치" 명령 형태 → 리플레이/멀티 대비

## 검증 방법
- `npm run test` : 타겟팅, 데미지, 엘릭서 충전, 덱 순환, 승리 판정 단위 테스트
- `npm run dev` 후 Playwright(사전 설치된 Chromium)로 브라우저 실행 → 스크린샷으로 아레나/유닛/UI 확인
- 수동 플레이: 카드 배치 → 유닛이 다리를 건너 타워 공격 → 타워 파괴 → 결과 화면까지 한 판 완주
- `npm run build` 성공 확인 후 `claude/busy-ride-ao5cgk` 브랜치에 단계별 커밋·푸시
