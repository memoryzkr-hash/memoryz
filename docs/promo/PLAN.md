# 홍보 에이전트 기획서

> 블로그 · 인스타그램 · 쓰레드에 **알아서 글을 올리고 댓글을 관리하는** 에이전트.
> 사용자는 계정 연결(한 번)과 브랜드 정보·글 구성만 적어 두면, 그다음부터는 GitHub Actions가 정해진 시간마다 돌립니다.
> 계정 연결 방법은 [SETUP.md](SETUP.md)에 있습니다.

## 1. 한눈에 보기

```
            ┌──────────── 정해진 시간(슬롯)마다 ────────────┐
 config.yml │ ① 주제 정하기 → ② 레퍼런스 조사 → ③ 글 쓰기 → ④ 검수·고치기 │ → ⑤ 카드 이미지 → ⑥ 발행
 brand.md   └───────────────────────────────────────────────┘        블로그 / 인스타 / 쓰레드
 templates/
 references.md          30분마다: ⑦ 새 댓글 모으기 → ⑧ 분류 → 답글 / 숨김 / 사람에게 넘기기
 faq.md
                         실행마다: report.md(무엇을 했나) · inbox.md(사람이 볼 댓글) · 알림(선택)
```

- **주제 하나 → 플랫폼 세 곳**: 한 주제로 블로그 긴 글, 인스타 카드뉴스 + 캡션, 쓰레드 연결 글(타래)을 각각 그 플랫폼 문법에 맞게 씁니다.
- **좋은 레퍼런스 참고**: 매번 웹을 검색해 같은 주제로 반응이 좋은 글을 찾아 *후킹 방식·구성·키워드·해시태그*를 뽑고, 사용자가 `references.md`에 적어 둔 계정·글도 함께 봅니다. 문장은 베끼지 않고 패턴만 씁니다.
- **제공된 글 구성대로**: `promo/templates/*.md`에 적은 구성(예: "후킹 한 줄 → 공감 → 해결 3단계 → 후기 → CTA")을 그대로 뼈대로 씁니다.

## 2. 사용자가 준비하는 것

| 파일 | 내용 | 예시 |
| --- | --- | --- |
| `promo/config.yml` | 켤 플랫폼, 올리는 요일·시간, 자동/검토 모드, 댓글 정책 | 월·수·금 오전 9시, 인스타+쓰레드+워드프레스 |
| `promo/brand.md` | 무엇을 홍보하는지, 타깃, 말투, 강조점, 금지 표현, 링크 | "30대 직장인용 단백질 도시락 구독" |
| `promo/templates/blog.md` · `instagram.md` · `threads.md` | 플랫폼별 글 구성 | 블로그: 제목 공식, 소제목 순서, 마무리 CTA |
| `promo/references.md` | 참고할 계정·글 주소, 검색 키워드 | 잘 되는 경쟁 계정 3개 |
| `promo/faq.md` | 댓글 답변에 쓸 사실(가격, 배송, 영업시간…) | "배송은 평일 오후 2시 마감" |
| GitHub Secrets | 각 플랫폼 토큰, Anthropic API 키 | SETUP.md 참고 |

> "계정만 주면" — 실제로는 **아이디·비밀번호가 아니라 각 플랫폼이 공식으로 발급하는 토큰**을 받습니다.
> 비밀번호로 로그인해 화면을 대신 누르는 방식은 인스타그램·네이버 약관 위반이고 계정 정지 위험이 커서 쓰지 않습니다.

## 3. 플랫폼별 지원 범위

| 플랫폼 | 자동 발행 | 댓글 관리 | 방식 |
| --- | --- | --- | --- |
| 쓰레드 | ✅ 글 + 이어지는 타래(선택: 첫 글에 이미지) | ✅ 답글 · 숨김 | Threads API (`graph.threads.net`) |
| 인스타그램 | ✅ 카드뉴스(캐러셀 최대 10장) + 캡션 | ✅ 답글 · 숨김 | Instagram API (`graph.instagram.com` 또는 `graph.facebook.com`) — **프로페셔널(비즈니스/크리에이터) 계정 필요** |
| 워드프레스 | ✅ 글 + 대표 이미지 + 태그 | ✅ 답글 · 스팸 처리 | WordPress REST API + 애플리케이션 비밀번호 |
| 네이버 블로그 · 티스토리 | ⚠️ **발행본만 준비** (붙여넣기용 HTML + 알림) | ❌ (`inbox.md`에 안내만) | 네이버는 2020년 5월 글쓰기 API를 종료했고, 티스토리 Open API도 종료됨 |

네이버는 광고성 대량 발행을 막으려고 API를 닫았기 때문에, 브라우저 자동 조작으로 우회하면 저품질·제재 위험이 큽니다.
그래서 네이버/티스토리는 **글·이미지·태그까지 완성된 발행본**을 만들어 두고 알림을 보내, 사람이 붙여넣고 발행 버튼만 누르게 합니다.

## 4. 글 만들기 흐름 (슬롯 1개 기준)

| 단계 | 하는 일 | Claude 설정 |
| --- | --- | --- |
| ① 주제 | `config.yml`의 `topics` 대기열을 먼저 쓰고, 없으면 콘텐츠 기둥(pillars)을 돌아가며 최근 30개 주제와 겹치지 않게 고름 | effort low |
| ② 조사 | web_search로 같은 주제의 인기 글을 찾고, `references.md`의 주소는 web_fetch로 읽음 → 후킹·구성·키워드·해시태그 패턴, 쓸 만한 사실(출처 포함) | web_search ≤ 5, web_fetch ≤ 5 |
| ③ 쓰기 | 브랜드 + 글 구성 + 조사 결과로 세 플랫폼 글을 한 번에 (같은 주제, 다른 문법) | effort high, structured output |
| ④ 검수 | 코드 규칙(글자 수, 해시태그 수, 금지어, 링크·광고 표기) + Claude 검수(과장·근거 없는 수치·의료/효능 표현·말투) → 문제 있으면 1회 고쳐 쓰기 | effort medium |
| ⑤ 이미지 | 카드뉴스 HTML 템플릿을 크롬으로 1080×1350 JPEG로 렌더링 → 공개 주소에 올림 | — |
| ⑥ 발행 | 켜진 플랫폼마다 발행, 결과(주소·ID)를 기록. 한 곳이 실패해도 나머지는 계속 | — |

- **자동 모드(`auto`)**: ④를 통과하면 바로 발행. 통과 못 하면 발행하지 않고 *검토 대기* 초안으로 남깁니다.
- **검토 모드(`review`)**: 항상 초안(`drafts/<id>.md`)만 만듭니다. 파일 맨 위 `status: draft`를 `approved`로 바꾸면 다음 실행 때 올라갑니다. 본문을 고쳐도 고친 대로 올라갑니다. `skip`이면 버립니다.
- **플랫폼마다 주기가 따로**: 블로그·인스타그램·쓰레드는 각자 켜고 끄고, 각자 요일·시간을 가져요(`platforms.<이름>.schedule`). 같은 시각에 차례가 겹친 플랫폼끼리는 주제 하나로 함께 만들어요.
- **같은 슬롯은 한 번만**: 슬롯 키(`2026-10-09@09:00`)를 기록해서 재실행·중복 실행에도 두 번 올리지 않습니다. 슬롯 시간이 6시간 넘게 지났으면 건너뜁니다(밀린 글 몰아 올리기 방지).

## 5. 댓글 관리

1. 최근 `lookbackDays`(기본 7일) 안의 게시물에서 새 댓글을 모읍니다(에이전트가 올린 글만 / 계정 전체 선택).
2. 내 계정 댓글, 이미 처리한 댓글, 이미 내가 답한 댓글은 건너뜁니다.
3. Claude가 분류하고 답글 초안을 씁니다. 댓글 내용은 **데이터로만** 취급합니다(댓글 속 "지시"는 따르지 않음).
4. 코드가 정책을 한 번 더 강제합니다.

| 분류 | 기본 동작 |
| --- | --- |
| 칭찬·감사 (`praise`) | 짧은 답글 (매번 다른 표현) |
| 질문 (`question`) | `faq.md`로 답할 수 있으면 답글, 아니면 사람에게 넘김 |
| 구매 의사 (`purchase`) | 안내 답글 + 설정한 링크 |
| 불만·환불·배송 문제 (`complaint`) | **사람에게 넘김** (답글 초안만 inbox에) |
| 민감(건강·법률·개인정보·언론) (`sensitive`) | **사람에게 넘김** |
| 스팸·광고 (`spam`) / 욕설·비방 (`abuse`) | 숨김 (워드프레스는 스팸 처리) |
| 기타 (`other`) | 무시 |

- 답글 안전장치: 글자 수 제한, 금지어 검사, `config.yml`에 없는 링크가 들어간 답글은 보내지 않고 사람에게 넘김.
- 한 번 실행에 답글 최대 `maxRepliesPerRun`개, 답글 사이 몇 초씩 쉬어 스팸처럼 보이지 않게 합니다.
- 사람에게 넘긴 댓글은 `inbox.md`에 게시물 주소·댓글·추천 답글과 함께 쌓이고, 알림 웹훅(슬랙/디스코드)을 설정하면 바로 알려 줍니다.

## 6. 실행 환경과 저장

- **GitHub Actions** (`.github/workflows/promo.yml`): 30분마다 `run`(발행할 슬롯이 있으면 발행 + 댓글 관리). 서버 비용 없음.
  Actions 탭에서 손으로 `run` / `post-now` / `comments` / `check` / `preview`를 실행할 수도 있습니다.
- **기록은 `promo-data` 브랜치**에 커밋합니다(코드 브랜치와 분리, CI도 안 돎).
  `state.json`(발행·댓글 기록), `drafts/`(초안), `media/`(카드 이미지), `exports/`(네이버·티스토리 발행본), `report.md`, `inbox.md`.
- **카드 이미지 공개 주소**: 인스타그램은 이미지를 공개 URL에서 내려받으므로, 이미지를 GitHub 저장소에 올리고 `raw.githubusercontent.com` 주소를 씁니다.
  코드 저장소가 비공개라면 이미지 전용 **공개 저장소**를 하나 만들어 `media.repo`에 적습니다.
- **토큰 자동 연장**: 쓰레드·인스타(인스타 로그인) 토큰은 60일짜리라, 7일마다 연장하고 새 토큰을 `PROMO_SECRET_KEY`로 암호화(AES-256-GCM)해 `promo-data`에 보관합니다. 키가 없으면 만료 14일 전부터 report에 경고합니다.
- **로컬 실행**: `npm run promo -- <명령>` — `.env` 파일이나 환경 변수로 키를 줍니다. `--dry-run`이면 어디에도 올리지 않고 결과만 파일로 남깁니다.

## 7. 명령

| 명령 | 하는 일 |
| --- | --- |
| `run` | 기본. 할 일이 있는 슬롯 처리 + 승인된 초안 발행 + 댓글 관리 + 토큰 연장 |
| `post-now [--topic "..."]` | 슬롯과 상관없이 지금 한 편 만들어 발행(검토 모드면 초안) |
| `preview [--topic "..."]` | 발행 없이 초안 + 카드 이미지만 만들기 (= `post-now --dry-run`) |
| `comments` | 댓글 관리만 |
| `check` | 설정 검사 + 각 플랫폼 토큰으로 내 계정 조회(아무것도 올리지 않음) |

## 8. 안전·정책 결정

| 항목 | 결정 | 이유 |
| --- | --- | --- |
| 로그인 방식 | 공식 API 토큰만 | 비밀번호 자동 로그인은 약관 위반·정지 위험 |
| 광고 표기 | `brand.disclosure`(예: "#광고", "협찬")를 설정하면 모든 글에 강제로 넣음 | 공정위 추천·보증 심사지침 |
| 사실 주장 | 조사 단계에서 출처가 있는 사실만 수치로 씀, 검수에서 근거 없는 수치·최상급 표현 지적 | 표시광고법, 신뢰 |
| 레퍼런스 | 문장·이미지 복제 금지, 구성·후킹 패턴만 참고 | 저작권, 플랫폼 중복 콘텐츠 제재 |
| 발행 실패 | 플랫폼별로 따로 기록, 실패한 곳만 다음 실행에 1회 재시도 | 한 곳 장애가 전체를 막지 않게 |
| 발행 한도 | 인스타 24시간 50개(API 제한), 쓰레드 250개, 답글 1,000개 — 에이전트는 기본 하루 몇 편이라 여유 | |
| Claude 모델 | `claude-opus-5-5` + 거절 시 서버 측 대체 모델 | 저장소의 다른 앱과 같음 |

## 9. 비용 감 (대략)

- 글 1편(세 플랫폼): Claude 호출 4~5번 + 웹 검색 최대 5번. 주 3편이면 한 달 약 13편.
- 댓글: 새 댓글이 있을 때만 30분마다 1번 호출(최대 30개 묶음). 댓글 없으면 Claude를 부르지 않습니다.
- **Anthropic 콘솔에서 월 사용 한도를 꼭 걸어 두세요.** GitHub Actions는 공개 저장소면 무료, 비공개면 월 무료 분(2,000분) 안에서 충분합니다(1회 1~3분).

## 10. 이번에 안 하는 것

| 안 하는 것 | 이유 / 대안 |
| --- | --- |
| 네이버·티스토리 자동 발행 | API 종료. 발행본 + 알림으로 대신 |
| DM 자동 응답 | 추가 권한·심사 필요, 실수 비용 큼. 구매 문의 댓글은 링크 답글로 |
| 릴스(영상) 자동 제작 | v2 후보 (카드 → 슬라이드 영상) |
| 성과 분석으로 다음 글 개선 | v2 1순위 — 인사이트 API로 반응 좋은 글의 패턴을 다음 주제·구성에 반영 |
| 웹 대시보드 | 지금은 `report.md` / `inbox.md` / Actions 요약으로 확인 |
