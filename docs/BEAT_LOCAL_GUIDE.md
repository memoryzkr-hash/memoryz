# 메아리 바운스 — 로컬에서 쓰기 안내서

음악이 한 마디 동안 멜로디를 **부르면**, 다음 마디에 들은 리듬을 **따라 쳐서** 음표 발판을 만들고 공이 그 위를 건너가는 리듬 게임입니다.
이 문서 하나로 설치부터 실행, 고치기까지 할 수 있게 정리했습니다. 기획 내용은 [BEAT_PLAN.md](BEAT_PLAN.md)에 있습니다.

---

## 1. 받은 파일

| 파일 | 무엇 | 언제 쓰나 |
| --- | --- | --- |
| `메아리바운스.html` | 게임 전체가 들어 있는 파일 하나(약 76KB) | **설치 없이 바로 플레이** |
| `memoryz-소스.zip` | 저장소 전체 소스 (`claude/busy-ride-ao5cgk` 브랜치) | 고치거나 직접 빌드할 때 |
| `테스트음원_126BPM.wav` | 박자가 또렷한 75초짜리 합성 음원 | "내 음악 불러오기"를 시험해 볼 때 |
| `사용설명서.md` | 이 문서 | |

## 2. 가장 빠른 방법: 파일 하나로 실행

1. `메아리바운스.html`을 **더블클릭**합니다. Chrome이나 Edge를 권장합니다. Safari와 Firefox도 동작합니다.
2. 곡을 고르면 바로 시작합니다. 소리는 처음 클릭한 다음부터 납니다(브라우저 정책).

- 서버도 설치도 필요 없습니다.
- 인터넷이 없으면 글꼴만 기본 글꼴로 바뀌고 나머지는 그대로 됩니다.
- 기록(최고 점수·등급)은 그 브라우저에 저장됩니다. 파일을 다른 폴더로 옮기면 기록이 따로 잡힐 수 있습니다.
- **폰에서 하려면** 파일을 폰으로 보내 브라우저로 열거나, 아래 4장의 `--host` 방법을 쓰세요.

## 3. 플레이 방법

### 기본 규칙
- **잘 들어** 마디: 멜로디가 나오고, 오선 위에 음표가 저절로 생겨 공이 밟고 지나갑니다.
- **따라 쳐!** 마디: 빈 오선입니다. 방금 들은 리듬대로 누르면 누른 자리에 음표가 생기고, 공이 그걸 밟습니다.
- 박자를 **너무 크게 틀리면** 음표가 깨져서(BAD) 공이 떨어지고 **목숨 −1**입니다. 목숨을 다 잃으면 처음부터 다시 합니다.
- 한 구절을 완벽하게 따라 치면 목숨 +1(시작 개수까지).

### 조작

| | 키보드 | 터치 |
| --- | --- | --- |
| 따라 치기 (쉬움·보통) | `Space` 등 아무 키 | 화면 아무 데나 |
| 따라 치기 (어려움) | `↓` `S` `D` `F` 낮은 음 / `↑` `W` `J` `K` 높은 음 | 왼쪽 절반 낮은 음 / 오른쪽 절반 높은 음 |
| 곡 고르기 | `↑` `↓` 곡, `←` `→` 난이도, `Enter` 시작 | 곡을 누르면 시작 |
| 일시정지 / 처음부터 | `Esc` / `R` | 오른쪽 위 ⏸ |

### 난이도 (같은 곡, 다른 악보)

| 난이도 | 따라 칠 음 | 허용 오차 | 목숨 |
| --- | --- | --- | --- |
| 쉬움 | 구절마다 센박 2음 | ±150ms | 5 |
| 보통 | 멜로디 전부 | ±120ms | 3 |
| 어려움 | 멜로디 전부 + 높은/낮은 음 구분 | ±95ms | 3 |

### 점수
판정 점수(PERFECT 300 · GREAT 200 · GOOD 100) × **콤보 배율**(50콤보에 2배) + 완벽한 구절마다 500점.
화면 오른쪽 위에 실시간으로 올라가고, 곡 × 난이도별 최고 점수가 저장됩니다.

### 설정 (곡 목록 아래)
- **메아리 그림자**: 따라 칠 자리에 점선 힌트를 보여 줍니다. 끄면 귀로만 칩니다.
- **무한 목숨**: 연습용입니다. 기록은 저장하지 않습니다.
- **싱크 조절**: 블루투스 이어폰처럼 소리가 늦게 나오면, 딸깍 소리에 맞춰 8번 두드려 자동으로 맞춥니다.

## 4. 내 음악 불러오기 (NCS 곡 등)

1. 곡 목록 아래 **"＋ 내 음악 불러오기"**를 누르고 MP3·WAV·OGG 파일을 고릅니다.
2. 몇 초 동안 분석합니다. BPM, 마디 첫 박, 8분음표 칸마다 실제로 치는 소리를 찾습니다.
3. 곡 목록 맨 위에 그 곡이 생깁니다. 이름은 MP3 태그(제목·아티스트), 태그가 없으면 파일 이름입니다.
4. 따라 치기 마디는 **그 곡이 그 마디에서 실제로 치는 리듬**입니다. 난이도에 따라 고르는 음 수가 달라집니다.

- 파일은 브라우저 안에서만 쓰이고 어디로도 보내지 않습니다.
- 불러온 곡은 페이지를 닫으면 목록에서 사라집니다. 다시 열면 다시 불러와야 합니다.
- 비트가 또렷한 곡(EDM·팝)이 잘 맞습니다. 박자가 흐린 곡이면 "조금 어긋날 수 있어요"라고 알려 줍니다.
- 네 박 모두 같은 세기로 킥이 들어가는 곡은 마디 첫 박을 한 박 어긋나게 잡을 수 있습니다. 리듬 자체는 맞습니다.

> **라이선스 주의** — NCS 곡은 유튜브·트위치 영상에는 무료지만, **게임에 넣어 배포하려면 NCS 상업 라이선스를 받아야 합니다**
> ([NCS 사용 정책](https://ncs.io/usage-policy)). 그래서 이 게임에는 NCS 음원이 들어 있지 않습니다. 본인 파일로 개인적으로 플레이하는 용도입니다.
> 기본 4곡(노을 점프·계단 도시·한밤 오락실·드롭 라인)은 게임 안 작곡기가 직접 만든 곡이라 이런 제한이 없습니다.

## 5. 개발 환경으로 실행하기 (고치고 싶을 때)

### 준비물
- **Node.js 22 이상** — https://nodejs.org 에서 LTS를 설치합니다. 터미널에서 `node --version`으로 확인할 수 있습니다.
- (선택) **git**

### 소스 받기 — 둘 중 하나

**A. 받은 zip으로**
```bash
# memoryz-소스.zip 압축을 풀고 그 폴더로 이동
cd memoryz
```

**B. GitHub에서**
```bash
git clone https://github.com/memoryzkr-hash/memoryz.git
cd memoryz
git checkout claude/busy-ride-ao5cgk
```

### 설치와 실행
```bash
npm ci            # 처음 한 번: 패키지 설치 (npm ci가 안 되면 npm install)
npm run dev       # 개발 서버 시작
```
브라우저에서 **http://localhost:5173/beat.html** 을 엽니다. 코드를 고치면 저장하는 순간 화면에 바로 반영됩니다.

**폰으로 시험하기** (컴퓨터와 같은 와이파이)
```bash
npm run dev -- --host
```
터미널에 뜨는 `Network: http://192.168.x.x:5173/` 주소 뒤에 `beat.html`을 붙여 폰에서 엽니다.

### 자주 쓰는 명령

| 명령 | 하는 일 |
| --- | --- |
| `npm run dev` | 개발 서버 (http://localhost:5173/beat.html) |
| `npm test` | 테스트 전체 (메아리 바운스는 `tests/beat/`) |
| `npx vitest run tests/beat` | 메아리 바운스 테스트만 |
| `npm run typecheck` | 타입 검사 |
| `npm run build` | `dist/`에 배포용 빌드 (모든 페이지) |
| `npm run build:beat` | 빌드 + **단일 파일** `dist/beat-standalone.html` 만들기 (받은 `메아리바운스.html`과 같은 것) |
| `npm run preview` | 빌드 결과를 로컬 서버로 확인 |

## 6. 고치기: 어디를 바꾸면 되나

### 파일 구조
```
beat.html                     페이지 (곡 목록·일시정지·결과·싱크 화면의 HTML)
src/beat/
  main.ts                     게임 흐름: 곡 선택 → 카운트인 → 플레이 → 결과, 입력, 내 음악 불러오기
  beat.css                    화면 디자인
  core/                       게임 규칙 (브라우저 없이 테스트됨)
    compose.ts                작곡기: 스타일 시트 + 시드 → 곡 (섹션·코드·멜로디)
    levels.ts                 수록곡 4개의 스타일 시트와 색
    charts.ts                 난이도별 악보 (작곡곡 / 불러온 음원)
    echo.ts                   핵심 규칙: 공 궤적, 판정, 깨진 음표, 목숨, 점수
    analyze.ts                음원 분석: BPM, 마디 첫 박, 리듬, MP3 태그
    judge.ts                  판정 구간(ms), 등급, 타이밍 분포
    records.ts                기록·설정 저장 (브라우저 localStorage)
    constants.ts              속도·음표 크기·목숨 기본값 등
  audio/music.ts              소리: 합성 밴드, 녹음 재생, 오디오 시계
  render/draw.ts              캔버스 그리기: 오선·음표·공·점수판
  ui/screens.ts               곡 목록·난이도 탭·결과 화면
tests/beat/                   테스트 (규칙, 작곡기, 4곡×3난이도, 분석기)
scripts/build-beat-standalone.mjs   단일 파일 만들기
docs/BEAT_PLAN.md             기획서
```

### 자주 바꿀 만한 것

**새 곡 추가** — `src/beat/core/levels.ts`의 `TRACKS` 배열에 하나를 더 넣습니다. 시드만 바꿔도 전혀 다른 멜로디가 나옵니다.
```ts
{
  id: 'my-song',                     // 기록 저장용 고유 이름
  name: '새 곡',
  tagline: '하우스 · 신나는 8분음표',
  palette: { skyTop: '#5b2a86', skyBottom: '#f28f3b', staff: '#fff6e8', ink: '#1a0b2e', accent: '#2ee6d6', ball: '#fffaf0' },
  style: {
    seed: 101,                       // ← 바꾸면 멜로디가 바뀜
    bpm: 120, root: 55, scale: MAJOR, range: [65, 83], lead: 'square',
    chords: { verse: [0, 5, 3, 4], chorus: [3, 4, 0, 0], bridge: [5, 3, 4, 4] },
    form: [['intro', 2], ['verse', 4], ['chorus', 4], ['outro', 2]],
    energy: { intro: 1, verse: 2, chorus: 3, bridge: 1, outro: 1 },
    ...POP,                          // 드럼·베이스 패턴: POP, FUNK, CHIP, EDM
  },
},
```
`npm test`를 돌리면 새 곡도 "정박으로 치면 S 클리어 / 안 치면 게임 오버"가 3난이도 모두 자동으로 검사됩니다.

**난이도 수치** — `src/beat/core/charts.ts`의 `DIFFICULTIES`(허용 오차 `catchMs`, 목숨 `hearts`, 두 키 `twoKeys`). 쉬움에서 구절당 칠 음 수는 `EASY_MAX`입니다.

**점수** — `src/beat/core/echo.ts`의 `SCORE_POINTS`(판정별 점수), `PHRASE_BONUS`, `comboMultiplier`.

**판정 구간** — `src/beat/core/constants.ts`의 `WINDOW_MS`(PERFECT ±45ms, GREAT ±90ms).

**불러온 음원 악보의 밀도** — `charts.ts`의 `AUDIO_PICK`(난이도별로 몇 %의 센 소리를, 마디당 몇 개까지 고를지).

**색** — 곡마다 `palette`, 곡 목록 등 화면 전체는 `beat.css` 맨 위 `:root`.

고친 다음에는 `npm test`로 확인하고, 단일 파일이 필요하면 `npm run build:beat`를 실행합니다.

## 7. 문제 해결

| 증상 | 해결 |
| --- | --- |
| 소리가 안 나요 | 화면을 한 번 클릭한 뒤 곡을 시작하세요. 곡 목록 아래 "소리 켬/끔"과 기기 음량도 확인하세요. |
| 박자가 밀려요 (특히 블루투스 이어폰) | 곡 목록 아래 **싱크** → 딸깍 소리에 맞춰 8번 두드리기 → 완료 |
| 불러온 곡의 박자가 이상해요 | 비트가 또렷한 곡으로 해 보세요. 분석 결과 BPM이 실제의 절반이나 두 배로 잡히는 곡도 있습니다(알려 주시면 고치겠습니다). |
| `npm ci`가 실패해요 | `node --version`이 22 이상인지 확인하세요. 그래도 안 되면 `npm install`을 쓰세요. |
| `localhost:5173`이 안 열려요 | 터미널에 뜬 주소(포트가 다를 수 있음) 뒤에 `/beat.html`을 붙이세요. |
| 기록이 사라졌어요 | 기록은 브라우저 저장소에 있습니다. 시크릿 창, 다른 브라우저, 다른 파일 위치에서는 따로 저장됩니다. |

## 8. 같은 저장소의 다른 페이지
`npm run dev` 후 같은 서버에서 열 수 있습니다.
- `/` — Memoryz Royale (카드 배틀)

- `/assistant.html` — 개인 비서
- `/beat.html` — **메아리 바운스**
