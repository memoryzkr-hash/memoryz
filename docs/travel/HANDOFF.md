# 여행 플래너 — 인수인계

이어서 개발할 사람(또는 Claude Code)이 먼저 읽을 문서입니다. 실행 방법은 `docs/travel/LOCAL_SETUP.md`, 실시간 지도 확장은 `docs/travel/REALTIME_MAP.md`.

## 무엇을 하는 앱인가

1. **대화로 계획** — 챗봇이 한 번에 하나씩 묻고(여행지 → 기간 → 동행·인원 → 1인 예산 → 일정 밀도 → 하고 싶은 것 → 현지 이동 → 첫날 출발),
   요약 카드에서 고친 뒤 Claude가 날짜별 방문지(좌표 포함)를 짭니다. 이후 같은 대화에서 "동선 최적화·교통비 줄이기"(즉시 계산)나
   "더 여유롭게" 같은 말로 고칩니다(Claude가 현재 일정을 받아 다시 씀).
2. **예측** — 시간·비용은 AI가 아니라 공식으로 계산합니다. 같은 일정이면 같은 숫자.
3. **시뮬레이션** — 3D 지도 위에서 여행자가 시간표대로 이동, 카메라가 따라감. 쓴 돈·거리 실시간 표시.

## 지켜 온 설계 원칙

- **AI는 "어디를"만, 숫자는 엔진이.** Claude가 준 요금·시간은 쓰지 않습니다. `core/`는 DOM·네트워크 없이 테스트 가능한 순수 함수.
- **네트워크는 있으면 더 좋게, 없으면 그대로.** 지도·도로·지형이 막혀도 같은 화면이 무지 배경에서 동작합니다.
  도로 경로(`ui/roadbook.ts`)는 엔진에 `RoadLookup` 함수로만 들어갑니다(`core/roads.ts`).
- **AI 응답은 믿지 않고 검사.** `core/validate.ts`가 좌표 범위·시간 형식·개수 제한을 확인하고 이상한 장소는 버립니다.
- **대화 흐름은 데이터.** `chat/flow.ts`의 `STEPS` 배열만 고치면 질문을 더하거나 순서를 바꿀 수 있고, 테스트(`tests/travel/chat.test.ts`)가 확인합니다.
- **키가 필요한 것은 사용자의 것만.** Anthropic 키는 사용자가 넣어 브라우저에만 저장. REST 키(카카오모빌리티 등)를 쓰게 되면 반드시 프록시.

## 계산 규칙 요약 (`core/modes.ts`, `core/regions.ts`, `core/schedule.ts`)

- 거리 = 직선거리 × 수단별 우회 계수 (실제 도로 경로가 있으면 그 거리)
- 시간 = 수단별 고정 대기(역까지 걷기·공항 수속) + 거리 ÷ 속도, 출퇴근(07:30–09:30, 17:30–19:30) 도로 수단 ×1.35
- 요금 = 나라별 요금표(KR·JP·FR·US·TH·기타). 택시·렌터카는 4명당 1대, 대중교통·기차·비행기는 1인 × 인원. 미터 단위 반올림
- 숙박 = 1박 요금 × (인원/2 올림)실 × (일수−1)박. 원화 환산은 고정 환율
- 경고: 마감 후 도착, 23시 넘김, 30분 넘는 도보, 하루 이동 4시간 초과, 예산 초과
