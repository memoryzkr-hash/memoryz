# 03 데이터 설계 — 개인 비서

> 입력: [01-scope.md](01-scope.md), [02-screens.md](02-screens.md) · 다음 단계: 04 구현
> 모든 데이터는 이 브라우저의 `localStorage`에만 저장합니다. 서버는 없습니다.

## 1. 공통 규칙

### 글자 수 세기 (이모지·한글)
- **눈에 보이는 글자 1개 = 1글자**로 셉니다. `Intl.Segmenter('ko', { granularity: 'grapheme' })`를 씁니다.
  - `한` = 1, `a` = 1, `🙂` = 1, `👨‍👩‍👧` (가족 이모지) = 1, `🇰🇷` (국기) = 1
- `string.length`와 HTML `maxlength`는 **쓰지 않습니다.** 이모지를 2글자 이상으로 세서, 화면에 보이는 숫자와 실제 제한이 달라집니다.
  (글의 예제에서 브라우저 테스트가 실패한 원인이 이것입니다.)
- 길이는 앞뒤 공백을 지운(`trim`) 뒤에 셉니다. 공백만 있는 입력은 "빈 값"입니다.
- 글자는 저장 전에 `normalize('NFC')`합니다 (맥에서 붙여 넣은 한글이 자모로 쪼개져 들어오는 경우 대비).

### 한 줄 / 여러 줄
| 종류 | 줄바꿈 | 해당 필드 |
| --- | --- | --- |
| 한 줄 | 줄바꿈을 공백 1칸으로 바꿈 | 주제 이름, 일정 제목, 장소, 받는 사람 이름 |
| 여러 줄 | 허용 | 일정 메모, 하고 싶은 말, 초안 |

### 날짜와 시간
- **날짜**는 `YYYY-MM-DD` 문자열 (그 사람의 달력 날짜). 실제로 있는 날짜인지 코드로 확인합니다 (`2026-02-30` ✗).
- **시간**은 `HH:mm` 24시간 문자열 (`15:00`).
- **시간대**는 일정을 만들 때 브라우저 시간대(`Intl.DateTimeFormat().resolvedOptions().timeZone`, 보통 `Asia/Seoul`)를 같이 저장합니다.
- **기록용 시각**(`createdAt` 등)은 ISO 8601 UTC 문자열 (`2026-10-06T08:12:00.000Z`).
- **오늘**은 브라우저 시간대 기준 날짜입니다.
- **한 주**는 월요일 ~ 일요일입니다.

### 상대 날짜 해석 규칙 (Claude에게 그대로 알려 줌)
Claude에게 매번 "오늘은 2026-10-06 (화), 시간대 Asia/Seoul"처럼 오늘 날짜를 함께 보냅니다.

| 표현 | 뜻 | 오늘이 2026-10-06 (화)일 때 |
| --- | --- | --- |
| 오늘 / 내일 / 모레 | +0 / +1 / +2일 | 10-06 / 10-07 / 10-08 |
| 이번 주 금요일 | 이번 주(월~일)의 금요일 | 10-09 |
| 다음 주 화요일 | 다음 주(월~일)의 화요일 | **10-13** |
| 화요일 (앞에 아무 말 없음) | 오늘 이후 가장 가까운 화요일, 오늘이 화요일이면 다음 주 | 10-13 |
| 3시 / 오후 3시 | `15:00` (오전이라고 안 하면 1~6시는 오후로) | 15:00 |
| 아침 9시 / 오전 9시 | `09:00` | 09:00 |

해석에 상대 표현이 쓰였으면 `interpretation`에 어떻게 읽었는지 한 줄로 적게 합니다 (확인 카드의 💡 줄).

### ID
`crypto.randomUUID()`로 만듭니다.

## 2. 저장소 키

모든 키에 `assistant.v1.`을 앞에 붙입니다. 값은 JSON 문자열입니다 (`apiKey`만 그냥 문자열).

| 키 | 값 | 없을 때 |
| --- | --- | --- |
| `assistant.v1.apiKey` | `string` | 시작 화면(S0)으로 |
| `assistant.v1.settings` | `Settings` | 기본값 사용 |
| `assistant.v1.topics` | `Topic[]` | `[]` |
| `assistant.v1.briefings` | `Briefing[]` (최신이 앞) | `[]` |
| `assistant.v1.events` | `Event[]` | `[]` |

**읽기 실패** (JSON이 깨짐, 모양이 틀림): 빈 값으로 시작하되 원래 글을 `<키>.corrupt`로 옮겨 두고,
위쪽에 "저장된 데이터 일부를 읽지 못했어요" 띠를 보여 줍니다. 원래 데이터를 조용히 덮어쓰지 않기 위해서입니다.

**쓰기 실패** (저장 공간 가득 참, 사생활 보호 모드): 오래된 브리핑부터 지우고 **한 번만** 다시 시도합니다.
그래도 실패하면 화면에 저장 실패 문구를 보여 주고, 화면에 있는 내용은 지우지 않습니다.

**메시지 입력·초안은 저장하지 않습니다.** 메모리에만 두어서 탭을 옮겨도 남고, 새로고침하면 사라집니다 (02단계 설계 그대로).

## 3. 데이터 모양과 검증 규칙

### Settings
| 필드 | 타입 | 기본값 | 제한 |
| --- | --- | --- | --- |
| `searchesPerTopic` | number | `3` | 정수 1~5 |
| `briefingLanguage` | `'ko+en'` \| `'ko'` | `'ko+en'` | 둘 중 하나 |

### API 키
| 규칙 | 오류 문구 |
| --- | --- |
| 앞뒤 공백 제거 후 `sk-ant-`로 시작 | "API 키 형식이 아니에요" |
| 중간에 공백 없음, 20자 이상 | "API 키 형식이 아니에요" |
| 시험 호출이 401 | "키가 맞지 않아요. 콘솔에서 다시 복사해 주세요" |

화면에는 끝 4자리만 보여 줍니다 (`sk-ant-…ab12`).

### Topic (관심 주제)
| 필드 | 타입 | 필수 | 제한 |
| --- | --- | --- | --- |
| `id` | string | ✓ | UUID |
| `name` | string | ✓ | 한 줄, 1~30글자 |
| `createdAt` | string | ✓ | ISO UTC |

| 규칙 | 오류 문구 |
| --- | --- |
| 비었거나 공백만 | (추가 버튼 비활성) |
| 30글자 초과 | 글자 수 빨간색, 추가 버튼 비활성 |
| 이미 있음 (대소문자·공백 무시하고 비교: `AI 도구` = `ai  도구`) | "이미 있는 주제예요" |
| 이미 5개 | "주제는 5개까지예요" |

- 만들기: 목록 끝에 추가 · 읽기: 만든 순서대로 · 수정: 없음 (지우고 다시 추가) · 삭제: 바로 삭제 + 되돌리기

### Briefing (브리핑 한 번)
| 필드 | 타입 | 필수 | 제한 |
| --- | --- | --- | --- |
| `id` | string | ✓ | UUID |
| `date` | string | ✓ | `YYYY-MM-DD`, 하루에 1개 |
| `createdAt` | string | ✓ | ISO UTC (마지막으로 받은 시각) |
| `language` | `'ko+en'` \| `'ko'` | ✓ | 받을 때의 설정 |
| `items` | `BriefingItem[]` | ✓ | 받을 때의 주제 수만큼 (1~5) |

### BriefingItem (주제 하나의 결과)
| 필드 | 타입 | 필수 | 제한 |
| --- | --- | --- | --- |
| `topicId` | string | ✓ | |
| `topicName` | string | ✓ | 받을 때의 이름을 복사해 둠 (나중에 주제를 지워도 기록에는 남게) |
| `status` | `'ok'` \| `'empty'` \| `'error'` | ✓ | |
| `bullets` | string[] | ok일 때 ✓ | 1~5개, 각 1~200글자, 한국어 |
| `sources` | `Source[]` | ok일 때 ✓ | 1~5개 |
| `error` | string | error일 때 ✓ | 화면에 보여 줄 문구 |

### Source (출처)
| 필드 | 타입 | 제한 |
| --- | --- | --- |
| `title` | string | 1~120글자 (넘으면 잘라서 `…`) |
| `url` | string | `https://`만 허용 |
| `lang` | `'ko'` \| `'en'` \| `'other'` | `en`이면 화면에 `[EN]` |

브리핑 규칙
- 같은 날 **다시 받기** → 그 날 브리핑을 통째로 바꿈 (하루 1개).
- 한 주제 **다시 시도** → 오늘 브리핑에서 그 주제 항목만 바꿈.
- **보관: 최근 30일.** 새로 저장할 때 30일보다 오래된 브리핑은 지웁니다.
- 수정·개별 삭제 없음. "모든 데이터 지우기"로만 지움.

### Event (일정)
| 필드 | 타입 | 필수 | 제한 |
| --- | --- | --- | --- |
| `id` | string | ✓ | UUID |
| `title` | string | ✓ | 한 줄, 1~50글자 |
| `date` | string | ✓ | `YYYY-MM-DD`, 실제 있는 날짜 |
| `start` | string \| null | | `HH:mm`. 없으면 **종일 일정** |
| `end` | string \| null | | `HH:mm`. `start`가 있어야 하고 `start`보다 늦어야 함 |
| `location` | string \| null | | 한 줄, 0~100글자 |
| `memo` | string \| null | | 여러 줄, 0~500글자 |
| `timeZone` | string | ✓ | 만들 때의 브라우저 시간대 |
| `source` | `'ai'` \| `'manual'` | ✓ | AI 해석으로 만들었는지 |
| `createdAt` / `updatedAt` | string | ✓ | ISO UTC |

| 규칙 | 오류 문구 |
| --- | --- |
| 제목 또는 날짜가 비어 있음 | (저장 버튼 비활성) |
| 50글자 초과 등 길이 초과 | 글자 수 빨간색, 저장 비활성 |
| `end`가 `start`보다 빠르거나 같음 | "끝 시간이 시작보다 빨라요" |
| `end`만 있고 `start`가 없음 | "시작 시간을 먼저 넣어 주세요" |
| `date`가 오늘보다 전 | 노란 경고 "이미 지난 날짜예요" (저장은 됨) |
| 일정이 이미 1000개 | "일정이 너무 많아요. 지난 일정을 지워 주세요" |

- 정렬: `date` → 종일 일정 먼저 → `start` 순.
- 목록 구역: **오늘** = 오늘 · **이번 주** = 내일 ~ 이번 주 일요일 · **나중** = 그 뒤 · **지난 일정** = 오늘보다 전.
- 수정하면 `updatedAt`만 바뀌고 `id`, `createdAt`, `source`는 그대로.

### 되돌리기 (주제·일정 삭제)
- 삭제하면 저장소에서는 **바로 지웁니다.**
- 지운 항목과 원래 위치를 메모리에 `{ kind, item, index }`로 **5초간** 들고 있다가, 되돌리기를 누르면 같은 자리에 다시 넣습니다.
- 5초가 지나거나 다른 항목을 지우면 이전 것은 버립니다. (02단계의 토스트 2초 → 되돌리기 토스트만 5초로 바꿈)

### 메시지 작성 (저장 안 함)
| 필드 | 타입 | 필수 | 제한 |
| --- | --- | --- | --- |
| `relation` | `'boss'`\|`'coworker'`\|`'friend'`\|`'family'`\|`'client'`\|`'custom'` | ✓ | |
| `customRelation` | string | custom일 때 ✓ | 한 줄, 1~20글자 |
| `name` | string | | 한 줄, 0~20글자 |
| `intent` | string | ✓ | 여러 줄, 1~500글자 |
| `tone` | `'polite'` \| `'casual'` | ✓ | 기본 `'polite'` |
| `event` | Event 복사본 \| null | | 일정 공유에서 왔을 때 |
| `drafts` | string[] | | 정확히 2개, 각 1~1000글자, 사용자가 고칠 수 있음 |

## 4. Claude에게 받을 응답 모양

세 가지 모두 **JSON으로만** 받고, 받은 뒤 코드가 위 검증 규칙으로 한 번 더 확인합니다.
JSON을 받는 방법(structured outputs 또는 `strict` 도구)은 04단계에서 SDK 문서로 확인해서 정합니다.
모델은 `claude-opus-5-5`입니다.

### 4-1. 브리핑 (주제 1개당 호출 1번)
- 주제마다 따로 부르고, 동시에 최대 2개까지 보냅니다 (화면의 "검색 중… (1/3)"과 주제별 다시 시도를 위해).
- 웹 검색 도구 `web_search_20260209`, 검색 횟수 `max_uses` = `settings.searchesPerTopic`.
- 보내는 정보: 주제 이름, 오늘 날짜, 언어 설정 ("한국어와 영어 기사를 찾고 요약은 한국어로" / "한국어 기사만").

```json
{
  "status": "ok",
  "bullets": ["요약 1", "요약 2", "요약 3"],
  "sources": [
    { "title": "기사 제목", "url": "https://example.com/news/1", "lang": "ko" }
  ]
}
```
- 최근 소식이 없으면 `{ "status": "empty", "bullets": [], "sources": [] }`.
- **출처 검사:** `sources[].url`이 그 호출의 실제 웹 검색 결과에 나온 주소인지 코드가 확인하고, 없는 주소는 버립니다
  (AI가 그럴듯한 링크를 지어내는 것을 막기 위해서). 남은 출처가 0개면 그 주제는 `error` "출처를 확인하지 못했어요"가 됩니다.

### 4-2. 일정 해석
- 보내는 정보: 사용자가 쓴 문장, 오늘 날짜·요일, 시간대, 위의 상대 날짜 해석 규칙.
- 웹 검색 안 씀.

```json
{
  "title": "민수 미팅",
  "date": "2026-10-13",
  "start": "15:00",
  "end": null,
  "location": "강남역",
  "memo": null,
  "uncertain": [],
  "interpretation": "'다음 주 화요일'을 10월 13일로 읽었어요"
}
```
- 모르는 칸은 `null`, 애매한 칸은 `uncertain`에 이름을 넣습니다 (`"title" | "date" | "start" | "end" | "location"`). 확인 카드의 노란 테두리가 됩니다.
- 코드가 `date`/`start`/`end` 형식이 틀렸거나 없는 날짜인 것을 찾으면 그 칸을 `null`로 바꾸고 `uncertain`에 추가합니다.
- 결과는 **바로 저장하지 않고** 확인 카드에 채우기만 합니다. 저장은 사용자가 누를 때 Event 규칙으로 검증합니다.

### 4-3. 메시지 초안
- 보내는 정보: 관계, 이름, 하고 싶은 말, 말투, (있으면) 일정 정보.
- 웹 검색 안 씀. 가벼운 일이라 effort를 낮춰 비용을 줄입니다.

```json
{ "drafts": ["초안 1", "초안 2"] }
```
- 2개가 아니거나 빈 초안이 있으면 실패로 보고 "초안을 받지 못했어요 [다시 시도]".

## 5. 캘린더 파일 (`.ics`)

| 항목 | 규칙 |
| --- | --- |
| 형식 | iCalendar 2.0, 줄 끝은 `\r\n` |
| 일정 ID | `UID:<event.id>@memoryz` |
| 시간 있는 일정 | `event.timeZone` 기준 시각을 UTC로 바꿔 `DTSTART:20261013T060000Z`. `end`가 없으면 시작 + 1시간 |
| 종일 일정 | `DTSTART;VALUE=DATE:20261013`, `DTEND;VALUE=DATE:20261014` (다음 날) |
| 글자 | `SUMMARY`(제목), `LOCATION`(장소), `DESCRIPTION`(메모). `\` `;` `,` 줄바꿈은 `\\` `\;` `\,` `\n`으로 바꿈 |
| 긴 줄 접기 | 한 줄이 **75바이트**(UTF-8)를 넘으면 접음. 한글은 1글자 3바이트, 이모지는 4바이트라 **글자 중간에서 자르지 않도록** 주의 |
| 파일 이름 | `<제목>-<날짜>.ics`. 제목의 `/ \ : * ? " < > |`와 공백은 `-`로 바꾸고 40글자에서 자름 |

## 6. 예시 데이터

```json
{ "id": "6f1c…", "name": "AI 도구", "createdAt": "2026-10-06T08:00:00.000Z" }
```
```json
{ "id": "a2b9…", "title": "민수 미팅 🍜", "date": "2026-10-13", "start": "15:00", "end": "16:30",
  "location": "강남역 11번 출구", "memo": "자료 USB 챙기기\n발표 10분", "timeZone": "Asia/Seoul",
  "source": "ai", "createdAt": "2026-10-06T09:00:00.000Z", "updatedAt": "2026-10-06T09:00:00.000Z" }
```
```json
{ "id": "c7d0…", "title": "엄마 생신", "date": "2026-10-18", "start": null, "end": null,
  "location": null, "memo": null, "timeZone": "Asia/Seoul", "source": "manual",
```

### 잘못된 예 (3)

| 데이터 | 틀린 곳 | 결과 |
| --- | --- | --- |
| 주제 `{ "name": "   " }` | 공백만 있음 | 추가 버튼 비활성 |
| 일정 `{ "title": "회의", "date": "2026-02-30", "start": "15:00", "end": "14:00", … }` | 없는 날짜 + 끝이 시작보다 빠름 | 날짜 칸 비우고 노란 표시, "끝 시간이 시작보다 빨라요" |
